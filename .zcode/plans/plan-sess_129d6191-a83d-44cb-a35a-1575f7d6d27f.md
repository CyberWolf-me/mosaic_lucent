# PERSIST → TEST → MEASURE → SEMANTICS → CLARITY

The approved spine, on a new branch off `ai-diagram-accuracy`. One reliable pattern throughout: pure logic in testable modules, thin wiring, live-gated.

## P0-1 — Persisted proposals (the immediate coding task)

Today a proposal is React state: a refresh drops the AI's proposed ops while the chat reply describing them survives — Lucent appears to lose work. `PersistedProposal` schema + load-time back-compat already drafted in `persistence.ts`; this batch finishes the lifecycle.

**Shape** (advisory's fields): `{ id, boardId, meetingId, turns, operations, status: "pending"|"approved"|"rejected"|"superseded", createdAt, request, explanation }`. The live `Proposal` type becomes this same shape with `status: "pending"` — one type, no dual bookkeeping; apply-time provenance derived from `meetingId + turns`.

**Transitions — idempotent, archiving:**
- `openProposal()` — mints `prp_…` id, writes `pending`. A pre-existing pending record first transitions to `superseded`.
- `applyProposal()` — synchronous `decisionRef` guard (double-click/replay = no-op), re-validates the batch against the CURRENT board via `applyValidOperations` (same one-simulator partial apply the server uses; a rehydrated proposal whose ops reference nodes deleted pre-reload applies its valid remainder and reports skips in chat), commits, transitions to `approved`.
- `cancelProposal()` — same guard, transitions to `rejected`. Reject ≠ destroy.
- **Archive**: terminal records push into `proposalHistory` on the project record (cap 10) — the audit trail of what Lucent proposed and what the user decided.
- **Wiring**: `persist()` reads the record from a ref (no churn at its ~8 call sites); every proposal path updates the ref first; all project-switch paths clear it so one project's proposal can't leak into another's autosave.
- **Rehydrate**: boot restores `pending` records into live state (terminal ones don't — approved ops are already on the board).
- **Meeting linkage**: `send(provenance)` maps `meetingId/turns` onto the record — a meeting proposal carries its transcript quote for the "Why?" loop.

**Tests**: record round-trip; back-compat (no status → pending; malformed → dropped); idempotent apply/reject (second call = no-op, zero duplicate commits); supersession ordering; rehydrate mapping; stale-ops partial apply. **Live gate**: proposal → hard reload → panel restored with batch intact → approve (board commits, record archives) → reject path likewise.

## P0-2 — Meeting-evaluation harness (measure, don't vibe)

- **Fixtures**: 5 scripted meetings in `packages/web/src/meeting-fixtures.ts` — product-launch, architecture (topic-jumping), brainstorm (maybe/disagreement), planning (owners/deadlines), and the messy one (interruptions, corrections, side chatter).
- **Offline suite** (`meeting-eval.test.ts`): drives the differential-loop policies against each fixture — trigger behavior, additive-auto-apply vs review gating, no-duplicate-region continuity, spatial stability across extracts.
- **Scoresheet**: `docs/16-meeting-evaluation.md` — the 8 metrics (capture, precision, semantic accuracy per kind, continuity, correction handling, attribution, 10-second readability, "why is this on the board?") as a repeatable protocol run against the real provider; failures feed P0-3.

## P0-3 — Semantic quality: statement kinds as data

- **Kinds on the record**: extracted nodes' provenance stamp gains `kind` (fact/proposal/question/decision/action/constraint/risk/problem) — deterministic from `classifyTurn` where decisive, model-declared otherwise.
- **Supersession**: a correction carries `supersedes` pointing at what it replaced; prompt teaches "update the existing node, don't duplicate, mark the replacement."
- **Corrections + ambiguity**: golden cases — "No, young professionals" ends as one corrected node; "talk to Sarah about pricing" yields *discuss pricing with Sarah*, never `assignee: Sarah`.
- **Attribution**: actions extract as `SET_ISSUE` with the speaking user as assignee, provenance quoting the words.
- Golden cases join `packages/ai/src/golden.ts`; eval gate stays 1.00.

## P1 — Visual clarity, minimal (only the two)

- **Selection focus**: selected node + edge-neighbors at full strength, rest subdued (opacity only; no data/layout/AI changes). Pure `focusSet()` helper + `DiagramLayer` prop + unit tests.
- **Region collapse**: region renders as `ARCHITECTURE · 24 nodes · 31 edges [Expand]`; expand returns exact prior geometry. Render-local state keyed by group id; culling respects collapsed regions; tests assert expand == pixel-identical.
- **Then stop.** Re-run readability at 20/40/80/150 nodes before anything heavier is discussed.
