# Lucent next milestone: trustworthy canvas + live meeting boards

Spec sentence (per review): *Lucent's AI owns meaning; the workspace engine owns state and geometry; the meeting engine owns continuous conversation; and user actions always outrank AI actions.*

Three separated problems, in order: rendering reliability → operation reliability → meeting intelligence. Implementation proceeds batch-by-batch, each gated (typecheck + affected suites + lint/format), with the review's concrete acceptance numbers.

## Milestone 1 — Canvas trustworthy

**1a. Connector dash fix (`pathLength={100}`).** Root cause of "disconnected midway": `.connectors path.appear` sets `stroke-dasharray: 320` as a *persistent* style (styles.css:1896-1900); the draw-in animation animates only `stroke-dashoffset`, so any edge >320px renders paint-gap-paint — arrowhead drawn, no line reaching it (styles.css:937-949). It also overrides the `4 4` dashed style meant for proposal edges. Fix: add `pathLength={100}` to every connector `<path>` (DiagramLayer.tsx:158-163), making dash units geometry-independent; `.appear` becomes `stroke-dasharray: 100 100` with keyframes sweeping `stroke-dashoffset 100→0` and `both` fill (final state: one continuous dash = solid line, any length); proposal `.dashed` edges get an opacity fade for their enter instead of competing dash animations; delete the dead `.drawing` rule and `--dash` fallback. **Verification per review: inspect COMPUTED STYLES, not just screenshots** — assert `getComputedStyle(path).strokeDasharray === "none"` after animation and non-empty path coverage between anchors for a >320px edge.

**1b. Edge drop during drag.** `visibleEdges` tests *undragged* positions and gets no keep set (DiagramLayer.tsx:110, culling.ts:213-230). Fix: pass the same `keep` set; test the span box against drag-shifted endpoints.

**1c. Dangling edges on old/imported boards.** `parseWorkspace` drops edges whose source/target id doesn't resolve and reports them in the result (tolerant load); render-time skip stays as belt (DiagramLayer.tsx:146).

**1d. Partial application — one canonical simulator (per review point 4).** No second semantics: `applyValidOperations(workspace, ops)` runs the SAME `validateOperations` simulation, then applies exactly the valid prefix-partition and returns `{workspace, applied, skipped: Array<{op, reason}>}` — validator and applier share one interpretation, so "validator ✓ / applier ✗" can't diverge. Server (generate.ts:595-602): when errors remain after the repair round, apply valid ops and return 200 with `operations` + `warnings`. Client chat shows "Applied 41 of 43 — 2 skipped: Payment→Stripe (target not found)" plus a **"Fix automatically"** affordance that sends ONLY the skipped ops for one bounded repair round. The room commit path (multiplayer log determinism) stays strict.

**1e. Repair budget + token ceilings.** `REPAIR_OPS_BUDGET` 2,000→12,000 chars; error list 8→20 (generate.ts:403-425; round count stays 1 per ADR 0011). Anthropic `max_tokens` 8192→16384 (large ops arrays truncate → 502, or models self-shorten and drop CONNECT_NODES — emitted last per dependency order); set explicit `max_tokens` in the OpenAI-compatible provider (unset today). Tool-description sentence: emitting all CONNECT_NODES matters more than label polish.

**M1 acceptance (the review's numbers):** a real-pipeline board with **50+ nodes, 70+ edges, 5+ regions, 10+ cross-region edges, multiple >320px edges, nodes at viewport boundaries, dragging while culling is active** → **70 generated = 70 valid = 70 rendered = 70 connected, 0 dangling, 0 disappearing during drag, 0 animation gaps.** Verified in DOM + computed styles; screenshot the before/after of one long edge.

## Milestone 2 — Lucent listens

**2a. Stable commits — the spatial-additivity invariant, written into the code:** *AI-generated additions must be spatially additive by default; existing committed objects keep their positions unless the user explicitly transforms.* New core export `relayoutRegion(workspace, groupId)` (reuses the existing private `splitByRegions`/`subWorkspaceFor`/`layoutSingle` in layout.ts) — relayouts ONLY the touched region at its existing origin; the commit path uses it when a batch's touched nodes fall within one region; full relayout remains for explicit whole-board transforms. Overlap separation: when a region grows past its neighbor's origin, shift only right-hand regions (deterministic, no global shuffle). Meeting-extract nodes also get a within-region pin pass.

**2b. Differential meeting loop.** `pendingTurns` per extract. Hybrid trigger — **configurable thresholds** (review point 12): (≥3 finals AND ≥4s silence) OR ≥8 finals OR 90s max-interval; 15s min debounce; one generation in flight, queue drains on stop. Differential prompt: "NEW turns since last extract; board already shows what's covered; add missing, connect to existing, new topics become new kind-regions; do NOT rebuild existing regions." Safe list per review point 6: CREATE_NODE, CONNECT_NODES, CREATE_GROUP, CREATE_SHAPE(sticky/text), SET_ISSUE auto-apply (≤12 ops); **ADD_COMMENT only when explicitly attributable to a speaker** (confidence-gated); anything with DELETE_*/TRANSFORM_DIAGRAM/large batches → review panel. UI: silent "✓ added" vs "⚠ Review required [Apply][Reject]".

**2c. Speaker identity + browser segment mode.** STT `onFinal` gains optional `{speaker?}` (types.ts); LiveKit segment participant/identity read (on the wire, untyped at livekit.ts:167-170); Web Speech gets per-utterance finals (today: one giant blob at stop — the accumulation in browser.ts:79-94); whisper documented single-final. MeetingView stops hardcoding "You"/"Speaker". "Sarah: I'll handle marketing" → task with `assignee: Sarah` via SET_ISSUE. **Confidence semantics (review point 10-11):** the extraction prompt instructs classifying extracted facts as decision (commit) vs proposal/question (labelled Consideration, no hard requirement) — "Maybe we could use Stripe" must NOT become a hard requirement.

**2d. Provenance + checkpoints.** Meeting-extract nodes carry `metadata: {meetingId, turnRange, transcript quote}`; node HUD shows "✨ Created by Lucent — Meeting, 04:32–04:51, 'For the first version we need…' [Jump to transcript]" — the board can always answer "why is this here?". Server: `appendTo(boardId, id, turns[])` on the MeetingStore + route (per-turn caps; jsonb read-modify-write, no schema change; in-memory + Postgres parity); MeetingView checkpoints per extract (no clearing); `stopRecording` auto-saves remaining turns.

**M2 acceptance (incl. review points 13-14):** scripted meeting with **topic switching** (Product → Pricing → Architecture → Marketing → BACK to Pricing → Launch) — must UPDATE the existing Pricing region, never create Pricing #1/#2/#3; **interruptions/corrections** ("students?" / "maybe later") must not become contradictory requirements; earlier topics NEVER move (position-assert across extracts); each extract = one undo step; transcript survives refresh; speaker-attributed actions land with owners; destructive mid-meeting request gates behind review.
